## Development workflow

1. Describe the goal and acceptance criteria for each feature.
2. Make focused changes with clear commit messages.
3. Add or update tests when functionality is introduced.
4. Keep setup and usage instructions current.

## Planning the first feature

Use this short specification when proposing a feature, so implementation and review have a shared definition of done:

| Field | What to record |
| --- | --- |
| Problem | The user task that O-AGENT- should solve |
| Inputs | What the agent receives and how those inputs are validated |
| Outputs | The expected result or artifact |
| Boundaries | What the agent must not access or modify |
| Success criteria | Observable examples of correct behavior |
| Testing | Automated tests and a manual verification command |

A feature is ready to merge when its documented success criteria pass, any new configuration is explained, and its behavior can be reproduced by another contributor.

## Contributing

1. Create a focused branch for a feature or fix.
2. Explain the change and its expected behavior in the pull request.
3. Add tests once executable code exists; avoid claiming tests passed before they run.
4. Review the diff for secrets, credentials, and unintended file changes.
5. Merge reviewed changes to `main` and keep this README up to date.

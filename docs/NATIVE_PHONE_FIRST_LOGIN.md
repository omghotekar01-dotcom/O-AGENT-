# O-AGENT native Android phone — first sign-in (private pilot)

This guide is for the **native Flutter Android pilot** and the private SaaS branch
`feat/saas-secure-control-plane-20261114`. Your phone's **Private HTTPS address**
is the private O-AGENT control-plane URL generated on **your PC**. It is **not** a
GitHub URL, an OpenAI API key, an 8-digit code, or `localhost`.

## First start on Windows

1. Install Node.js 22.12+, Docker Desktop and Tailscale on Windows. Start
   Docker Desktop and sign in to Tailscale.
2. Install Tailscale on Android, sign into the same private tailnet and enable
   its VPN connection. Enable MagicDNS and HTTPS certificates for your tailnet.
3. Use a complete checkout of this branch, not the Flutter-only source archive.
   Double-click **START-O-AGENT.cmd** from the repository root. It starts the
   private services, checks readiness, and registers the native OAuth client.
   If any diagnostic says `[FIX]`, address that first; do not disable TLS checks.
4. Double-click **SHOW-MOBILE-LOGIN.cmd** from the repository root.
   It reads `deploy/saas/free-pilot/.env.local` and prints **only** the
   configured address, such as `https://laptop.tailnet.ts.net:8443/`.
   The file is generated by the setup helper and must remain on the PC.
   The displayed address is not a live connectivity test.
5. On Android, open **O-AGENT > Private HTTPS address** and type that exact
   URL, including `:8443` if it is present. Check **Remember this phone**
   only on a phone you trust. Tap **Sign in to native app**.
6. On first sign-in, the Keycloak username is `pilot-owner` and the temporary
   password is `OAGENT_OWNER_PASSWORD` inside the private PC file
   `deploy/saas/free-pilot/.env.local`. Change that password and enable
   MFA. On subsequent logins, use **your new password**, not the old one.
7. On the PC, double-click **CONNECT-O-AGENT-WORKER.cmd**, select a folder
   you trust and leave the worker window open.
8. In the native app, go to **Devices > Enroll a new laptop**. Paste the one-time
   pairing link from the PC, verify the exact device fingerprint, and approve.
   Do not approve unfamiliar devices.
9. In **Work**, request a read-only workspace inventory. In **Inbox**, review
   the requested action and approve or deny it. Check real run status and
   results. Supported coding-session continuation requires installed and
   separately authenticated provider tools.

**Keep the PC running** while remotely controlling a local worker. This is a
private pilot and not a universally available ChatGPT-website remote-control API.

## Safely pull code into an existing Git checkout

Open PowerShell or Git Bash **inside the O-AGENT repository folder**, then run:

```powershell
git status --short
git fetch origin
git switch feat/saas-secure-control-plane-20261114
git pull --ff-only origin feat/saas-secure-control-plane-20261114
```

If your local feature branch has not been created yet, after `git fetch origin`
run `git switch --track origin/feat/saas-secure-control-plane-20261114`
instead. If Git reports uncommitted changes or divergent history, stop and
preserve your work. **Do not force-reset, delete local files, remove
Docker volumes, or overwrite private .env.local**. Git cannot pull into a
downloaded ZIP folder that lacks a `.git` directory; use a proper clone.

For a **new** folder, run:

```powershell
git clone --branch feat/saas-secure-control-plane-20261114 https://github.com/omghotekar01-dotcom/O-AGENT-.git
cd O-AGENT-
```

Don't replace an existing configured PC installation with a fresh copy unless
you deliberately plan to migrate its private settings and data. Never commit
or share your local .env.local, device keys, passwords, or pairing tokens.

## Common blockers

- **Blank Private HTTPS address:** Run SHOW-MOBILE-LOGIN.cmd on the configured PC.
- **Helper says pilot not configured:** Run START-O-AGENT.cmd and fix any
  prerequisite errors.
- **Phone cannot reach server:** Verify Tailscale on both devices, MagicDNS,
  HTTPS certificates, configured Serve route and that Docker services are ready.
- **Keycloak login fails:** Use the correct changed password and verify the
  native mobile OAuth registration completed.
- **Devices empty:** Start CONNECT-O-AGENT-WORKER.cmd, approve the matching
  fingerprint and keep the worker online.
- **No existing Codex threads:** Confirm Codex CLI is available, authenticated
  on the PC and associated with the enrolled project folder.

No new Android APK is needed for this Windows-side help improvement.
